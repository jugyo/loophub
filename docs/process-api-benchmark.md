# プロセス API 移行ベンチマーク

2026-08-23 に、`node:child_process` から Bun のプロセス API へ移行した前後を同じ作業ツリーで比較した。各ケースは10回実行し、subprocess 数はベンチマーク側から直接起動した回数である。

## 環境と手順

- Bun: `1.3.14`
- 作業ディレクトリ: LoopHub リポジトリのルート
- `LOOPHUB_HOME`: `/tmp/loophub-bench-388`
- `PATH`: 実行時の `PATH`（変更なし）
- 計測: `performance.now()`、各試行の subprocess 起動から終了まで
- 移行前: `node:child_process` の `spawnSync` / `spawn`
- 移行後: `Bun.spawnSync` / `Bun.spawn`

実行した代表コマンドは次のとおり。

- Git: `git rev-parse --verify HEAD`
- CLI: `bun cli/index.ts --help`
- worker: `sh -c 'exit 0'`（workflow / job queue の shell 実行）

## 結果

| ケース | subprocess 数 | 10試行のレイテンシ (ms) | 中央値 (ms) | 最小–最大 (ms) |
| --- | ---: | --- | ---: | ---: |
| Git / Node `spawnSync` | 10 | 14.716, 14.717, 14.803, 15.141, 15.152, 15.206, 15.723, 15.814, 16.244, 16.758 | 15.179 | 14.716–16.758 |
| Git / Bun `spawnSync` | 10 | 12.931, 13.437, 13.544, 13.635, 14.103, 14.553, 14.728, 15.017, 15.369, 15.993 | 14.328 | 12.931–15.993 |
| CLI / Node `spawnSync` | 10 | 29.904, 29.998, 30.180, 30.629, 30.991, 31.045, 31.253, 31.485, 31.768, 33.520 | 31.018 | 29.904–33.520 |
| CLI / Bun `spawnSync` | 10 | 29.214, 29.911, 30.065, 30.186, 30.199, 30.796, 30.866, 30.999, 31.240, 31.303 | 30.4975 | 29.214–31.303 |
| worker / Node `spawn` | 10 | 2.947, 3.220, 3.301, 3.427, 3.640, 3.832, 3.930, 3.932, 3.973, 4.786 | 3.736 | 2.947–4.786 |
| worker / Bun `spawn` | 10 | 2.784, 2.832, 2.877, 2.951, 3.053, 3.067, 3.259, 3.323, 3.472, 3.557 | 3.060 | 2.784–3.557 |

中央値は10値の中央2値の平均とした。移行後の中央値は Git 5.6%、CLI 1.7%、worker 18.1% 短縮した。subprocess 数は各比較で移行前後とも10回であり、回帰は観測されなかった。この測定は subprocess 起動部分の比較で、Git 自体や agent runtime の処理時間は変更していない。
